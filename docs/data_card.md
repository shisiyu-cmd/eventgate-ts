# 数据卡：Metro Interstate Traffic Volume（UCI #492）

本文件记录建模之前对原始数据的全部核查结论。文中每个数字都可以由
`python -m src.data.audit`（产出 `results/audit/audit.json`、`audit.md`）复现。

---

## 1. 来源与合规

| 项 | 值 |
|---|---|
| 数据集 | Metro Interstate Traffic Volume（UCI Machine Learning Repository, ID 492） |
| 原始地址 | `https://archive.ics.uci.edu/static/public/492/metro+interstate+traffic+volume.zip` |
| 观测点 | 美国明尼苏达州 Minneapolis–St. Paul 都会区 I-94 西向、MN-280 以东的 MN DoT 车站 301 |
| 采集方 | 明尼苏达州交通部（MnDOT），经 UCI 二次发布 |
| 许可 | UCI 站点公开数据；本仓库不再分发原始文件，仅提供 `scripts/download_data.py` 自动拉取 |
| 时间跨度 | 2012-10-02 09:00 → 2018-09-30 23:00（逐小时） |
| 文件 | `Metro_Interstate_Traffic_volume.csv.gz`（405,547 字节，48,204 行 × 9 列） |

字段：`holiday`、`temp`(K)、`rain_1h`(mm)、`snow_1h`(mm)、`clouds_all`(%)、
`weather_main`、`weather_description`、`date_time`、`traffic_volume`(veh/h)。

> 本数据只包含**一个**观测断面，没有车道级、车辆级或路网拓扑信息；因此本项目的
> 结论是"单点断面流量预测"，不能外推为路网级结论。这一限制在报告第 6 节再次说明。

## 2. 时间轴完整性（本项目最重要的数据事实）

逐小时网格应为 **52,551** 个小时，实际有记录的小时只有 **40,575** 个，
**缺失 11,976 小时 = 22.8%**。缺失不是均匀噪声，而是成段出现：

| 年份 | 有记录行数 | 该年缺失小时数 |
|---|---|---|
| 2012（10 月起） | 2,559 | 72 |
| 2013 | 8,573 | 1,466 |
| 2014 | 4,839 | 4,259 |
| 2015 | 4,373 | 5,167 |
| 2016 | 9,306 | 946 |
| 2017 | 10,605 | 47 |
| 2018（至 9 月） | 7,949 | 19 |

**2014-09 至 2015-05 存在约 9 个月的整段中断**（传感器/上报停摆），
这直接决定了：
1. 训练期不能假设"时间连续"，必须显式切分连续段（`seg` 标记）；
2. 任何滑动窗口都必须整段落在同一连续段内，否则窗口会跨越 9 个月的空洞；
3. 2014/2015 两年合计缺失 9,426 小时，占全部缺失的 78.7%。

在 2017–2018 年数据基本完整（缺失 66 小时），因此**测试年（2018）的数据质量显著
优于训练期**——这一点在方法论上很关键：模型在训练期见过大量"隔小时采样"的噪声
上下文，测试期则是干净序列。

## 3. 重复时间戳

`date_time` 并非主键：**7,629 行**落在已被占用的时间戳上（15.8%）。
逐组核对后得到两条结论：

1. 同一时间戳内 `traffic_volume` 的极差**恒为 0** —— 流量本身没有冲突，
   重复行来自天气标注的多次上报；
2. 冲突只出现在 `weather_main` / `weather_description` 上，典型例子是同一小时
   同时被打上 `Rain` 与 `Drizzle`、`Clouds` 与 `Overcast`。

处理方式：以时间戳为单位取**首行**（等价于"先到先得"），并在报告中声明该选择
对天气特征的影响上限——天气在这份数据里对 MAE 的贡献本就很弱（见第 5 节消融）。

## 4. 传感器与物理越界

| 检查项 | 结果 | 处理 |
|---|---|---|
| `traffic_volume == 0` | 2 行（均 2016 年），且不构成连续段 | 视为缺测，置 NaN |
| `temp == 0` K | 10 行（0 K 物理上不可能） | 置 NaN |
| `rain_1h` 最大值 | 9,831.3 mm/h（另 1 行 >50），p99.9 = 13.6 | >60 mm/h 置 NaN |
| `snow_1h` 最大值 | 0.51 mm/h，仅 63 行非零 | 取 `log1p`，不裁剪 |
| `clouds_all` 越界 | 0 | 不处理 |
| `holiday` 取值 | 11 种，61 行非 None | 见第 5 节：**不足以**刻画事件 |

`traffic_volume` 分布：均值 3,259.8、标准差 1,986.9、最小 0、最大 7,280、
q01 = 257、q99 = 6,702 —— 右偏但有明显双峰（夜间低谷 / 白天高峰）。

## 5. 事件字段的信息量不足

`holiday` 只有 61 行非空，且包含 **`State Fair`** 这类非联邦假日。逐年核对中国
"节假日效应"的建模需要的是**邻近效应**（节前一天的出行高峰、节后一天的恢复），
而不是一个 0/1 标记。因此管道里把 `holiday` 扩展为 3 维：

```
is_holiday         当天是否为假日
days_to_holiday    到最近假日的有符号天数（-3..+3）
holiday_kernel     exp(-(d/1.5)^2)，d 为到最近假日的天数
```

假日表由 `us_federal_holidays(year)` 按规则生成（含"某月第 N 个星期一"这类浮动
假日），并**额外并入数据里出现过的 `State Fair`**，避免规则表与数据打架。

天气 11 类被合并为 7 类（`Clear`/`Clouds`/`Rain`/`Snow`/`LowVis`(Fog+Mist+Haze)/
`Thunder`/`Squall`），原因是 `Smoke`(20 行)、`Squall`(4 行) 单独成类会退化成噪声，
而 `Fog`/`Mist`/`Haze` 的物理含义（能见度下降）对交通流的作用方向一致。

## 6. 清洗与插值的边界

- 只对 **`limit=2`** 的短缺口做时间插值，且限定 `limit_area="inside"`；
- 每个窗口携带 `vol_mask` 通道，**插值出来的点 mask=0**，真实观测 mask=1；
- 所有窗口的**目标 y 必须是真实观测**（不允许预测一个插值出来的值）；
- 插值占比：训练期 5.49%、验证期 0.23%、测试期 0.16%。

这条设计使得"数据质量"本身成为一个可分析的变量：模型的误差能否被
`vol_mask` / 缺口长度解释，是报告第 5 节的一个切片。

## 7. 已知偏差与不可消除的局限

1. **单点断面**：结论不外推到路网。
2. **2018 年无节假日高峰**与训练期不完全同分布（2018 年测试集只覆盖 1–9 月）。
3. **天气是"上报值"而非"物理真值"**：同一小时多标签，且天气标签来自机场观测站，
   与 I-94 断面存在空间错配。
4. **9 个月断档无法插值**，只能整段剔除；因此有效训练样本比名义值少。
5. `traffic_volume` 上限 7,280 是检测器量程，真实高峰可能被截断（右删失）。
