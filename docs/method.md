# 方法说明（数据层 → 方法层 → 分析层）

本项目把"用机器学习方法做数据分析"拆成三层，每一层的结论都能被下一层复现。
所有数字均来自仓库内脚本的真实输出（`runs/`、`results/`），未做任何手工修饰。

---

## 1. 数据层：先证明数据能不能用，再决定怎么用

数据源：UCI *Metro Interstate Traffic Volume*（明尼阿波利斯 I-94 西向，2012-10-02 至
2018-09-30 的逐小时数据），48,204 行 × 9 列。字段细节与审计证据见 `docs/data_card.md`。

### 1.1 审计发现（决定了后面所有设计）

| 发现 | 规模 | 对建模的后果 |
|---|---|---|
| 时间戳重复 | 7,629 行 | 同一小时的 `traffic_volume` **极差恒为 0**，冲突只在天气标签（如 `Rain`/`Drizzle` 同时出现），故按小时取首条即可，不会引入流量噪声 |
| 网格缺口 | 应有 52,551 小时，实际 40,575 个唯一小时 | 11,976 小时缺失；其中 **2014-09 ~ 2015-05 连续 9 个月全空**（4,259+5,167 小时） |
| 采样不连续 | 2,589 个连续段，段长中位数 2 小时 | 2013–2016 大量"隔一小时采一次"，不能把相邻行当成相邻小时 |
| 传感器异常 | `traffic_volume==0` 仅 2 行（均 2016）；`temp==0 K` 10 行；`rain_1h` 最大 9831.3 mm/h（另一行 >50，p99.9=13.6） | 需显式清洗，否则极端值主导损失 |
| 假日标注稀疏 | `holiday` 非空仅 61 行，且含 `State Fair` 这类非联邦假日 | 不能当作二值特征直接喂模型 |

**这四条直接否掉了"直接 resample 然后 LSTM"的做法**：那样会把 9 个月的空白当成连续序列，
并在隔小时采样区把 2 小时当成 1 小时。

### 1.2 处理规则

1. **去重**：按 `date_time` 取首条（流量无冲突，已在审计中验证）。
2. **重建小时网格**：`2012-10-02 09:00` → `2018-09-30 23:00` 全量 52,551 小时。
3. **清洗**（置 NaN，不删除行，以免破坏时间索引）：
   `temp <= 0 K`、`rain_1h > 60 mm/h`、`traffic_volume == 0`。
4. **短缺口插值**：仅对**内部**缺口做 `interpolate(method="time", limit=2)`，
   即最多补 2 小时；同时维护 `vol_mask ∈ {0,1}`，插值点为 0。
   插值占比：train 5.49% / val 0.23% / test 0.16%。
5. **长缺口不插值**：任何窗口（168 小时）或预测区间（24 小时）**跨越**缺口即丢弃，
   且**预测目标必须是真实观测**。这是本项目最重要的数据约束——它把"看起来很长"的
   48k 行压缩到 25,210 个合法样本。
6. **天气**：11 类原始标签合并为 7 类（`Fog/Haze/Mist/Smoke → LowVis`；`Drizzle → Rain`；
   `Thunderstorm → Thunder`；保留 `Squall`），因为 `Smoke` 只有 20 行、`Squall` 4 行。
7. **假日**：不用原始 `holiday` 列，而是按美国联邦假日规则生成日历，再展开为 3 维
   `is_holiday`、`holiday_kernel = exp(-(d/1.5)²)`（d 为距最近假日的天数，±3 天截断）、
   以及小时/星期/年日的正余弦编码。
8. **标准化**：只用**训练期**统计量（`mu`/`sd` 存于 `data/processed/windows_h24.npz`）。

### 1.3 窗口与切分

- 输入窗口 `L=168` 小时（一周），预测 `H=24` 小时（一天），**直接多步**（非递归）。
- 切分按时间：train ≤ 2017-06-30，val 2017-07-01~2017-12-31，test 2018-01-01~2018-09-30
  （共 15,605 / 3,660 / 5,945 个窗口）。
- 通道：`X_num`(6) + `X_cal`(7) + `X_cat`(7，天气 one-hot) + `X_ev`(18，事件描述符)。

## 2. 方法层：EventGate-TS

### 2.1 为什么是"事件门控 + 频域/时域双专家"

交通流量在一周内是强周期信号，**频域分支天然适合周周期**；但假日、暴雪、暴雨会让
周期结构整体错位，此时"周期外推"应当被抑制。于是设计一个**标量门控**
`g ∈ (0,1)^H`，按样本、按预测步决定"信频域还是信时域"。

### 2.2 结构

```
vol_n  = RevIN(vol)                                  # 逐窗口实例标准化
h_time = LayerNorm( pool([mean_t PatchTST(·), last_t]) )       # 时域专家表示
p_t    = head_time( dropout(h_time) )                          # [B, H]
p_f    = head_freq( dropout(FreqBranch(x)) )                   # [B, H]，全通道卷积
g      = sigmoid( MLP([p_f, p_t, |p_f - p_t|, e]) )            # e = 18 维事件描述符
delta  = g ⊙ p_f + (1-g) ⊙ p_t
ŷ_z    = vol_n[:, -1] + delta                                  # 残差/增量头
ŷ      = RevIN⁻¹(ŷ_z)
```

- **`FreqBranch`**：对输入做 `rFFT`，保留前 `k=8` 个系数重建低频（周趋势），
  原序列减低频得高频残差；两条带各过一个 `Conv1d(width=32, k=7)` + 均值池化 + `Linear`。
- **残差头**：输出的是"相对最后一个观测的增量"，这是让 NN 能与 GBDT 可比的关键——
  没有它，网络必须先回归量级再回归形状，单步 MAE 从 157 恶化到 216。
- **门控输入包含两个专家的预测值与分歧** `|p_f-p_t|`，因此门控能"看到"专家是否吵架；
  事件描述符使其能按上下文调制。
- 参数量：396,424（`no_freq` 版本 364,440，恰好与 PatchTST 同容量）。

### 2.3 损失与训练

- 点预测：`SmoothL1(β=100)`（对极端流量的鲁棒性优于 MSE）。
- 概率预测：三分位头（0.1/0.5/0.9）用 pinball loss + `0.5×L1(中位数)` 辅助项。
- AdamW（lr 1e-3，wd 1e-2）+ OneCycleLR，batch 256，最多 180 epoch，
  early stopping patience 12（监控 val MAE），3 个随机种子报告 mean±std。

### 2.4 消融开关（同一份代码、同一数据、同一超参）

| 开关 | 含义 |
|---|---|
| `--no_freq` | 去掉频域专家（退化为单专家门控） |
| `--no_gate` | 门控固定为 0.5（等权平均） |
| `--no_ev` | 门控输入置零（去掉事件描述符） |
| `--no_revin` | 去掉实例标准化 |
| `--volstats` | 追加手工 lag/rolling 特征（模拟 GBDT 的特征工程） |
| `--n_q 3` | 三分位概率头 |

### 2.5 对照基线

- 朴素法：`naive_t-1`、`seasonal_24`、`seasonal_168`、`seasonal_avg_24_168`、`drift_24`
- 树模型：LightGBM（按 horizon 每步一个模型，滞后/滚动/日历/天气/事件共 71 维特征）
- 神经基线：LSTM、TCN、PatchTST-lite、MLP（**全部使用同一个残差头**，保证公平）

## 3. 分析层：四个可证伪的问题

1. **谁更好，好多少，是否显著？**
   配对检验：Diebold-Mariano（Newey-West 长期方差）+ Wilcoxon 符号秩 +
   按 24 小时分块的 block bootstrap 置信区间（2000 次）。
2. **误差在哪里？** 10 个切片的 MAE/RMSE/bias：预测步、日型（工作日/周末/假日）、
   天气、需求分位、6 小时趋势、降雨/降雪量级、流量 z-score、窗口结束小时。
3. **门控到底在做什么？** 逐 horizon 的平均门控、按情境的门控分布、
   门控对"专家分歧"的 Spearman 相关、用事件描述符/专家输出线性解释门控的 R²；
   **因果结论一律由重新训练的消融给出**（因为两个专家是联合训练的，
   单独取出的专家不是有效反事实——这一点在代码注释里明确写了）。
4. **缺数据时会怎样？** 两种破坏：`gap`（最近 k 小时不可用，模拟检测器掉线）
   与 `block`（窗口内随机连续 k 小时缺失）。缺失值填训练均值并把 mask 置零，
   **所有模型在同一份破坏数据上评估**，LightGBM 每个条件重新训练。

概率预测用 PICP / PINAW / pinball / CRPS 评估，三条路线对比：
原生分位头、LightGBM + 验证集残差分位、季节基线 + 残差分位。

## 4. 可复现性

```bash
python scripts/download_data.py            # 下载并解压原始数据
python -m src.data.audit                   # 数据审计 -> results/audit/
python -m src.data.build                   # 构造窗口 -> data/processed/
python -m scripts.run_matrix --stage main  # 主实验（NN）
python -m src.models.baselines             # 朴素法与 LightGBM
python -m scripts.run_analysis             # 切片/门控/校准/鲁棒性/检验/图
```

所有随机性均固定种子；`runs/<model>-h24-s<seed>/metrics.json` 保存了完整配置
（`config` 字段即 `argparse` 命名空间），因此任何一条结果都能被反查到超参。
